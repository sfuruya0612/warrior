# ADR-003: 記録中のトレーニングは開始した端末だけが編集する

- Status: Accepted

## Context

記録中のトレーニングは、始めた端末でだけ編集できる。
ほかの端末では閲覧のみとする (REQ-NFR-015)。
始めた端末が使えなくなった場合に備えて、ほかの端末から、サーバーに保存済みの内容で記録を引き継ぐ操作を用意する (REQ-NFR-015)。
トレーニングの終了後に編集が重なった場合は、後から保存した内容を残す (REQ-NFR-015)。
記録はアカウントに紐づけてサーバーに保存し、複数の端末から同じ記録を見られる (REQ-NFR-006)。

## Decision

トレーニングを開始した端末に、そのトレーニングの **編集権** を紐づける。
編集権はトレーニングごとに持つ。
引き継ぎは、対象のトレーニングの編集権だけを移す。
編集権はアカウントではなく、端末のブラウザに保存した推測できない端末トークンに紐づける。
端末トークンは利用者に属し、認証中のアカウントと一致する場合だけ編集権を認める。
ログアウトの後も同じ利用者でログインし直せば、記録中のトレーニングの編集権を再接続できる。
別のアカウントに切り替えたときは、前の利用者の端末トークンを破棄する。
サーバーは端末トークンの SHA-256 のハッシュを D1 に保存し、書き込みのたびに照合する。
端末トークンは HttpOnly、Secure、SameSite=Lax の Cookie で送る。
ただし、ローカル開発の `http://localhost` では Safari が Secure の Cookie を保存しないため、`ORIGIN` が HTTP のときは Secure を付けない。本番の HTTPS では必ず付ける。
API の応答とログには出さない。

サーバーは、編集権を持たない端末からの記録中の書き込みを拒否する。
ほかの端末は、サーバーに保存済みの内容を閲覧できる。

引き継ぎは、ほかの端末で利用者が明示的に操作したときにだけ行う。
引き継いだ端末は、サーバーに保存済みの内容を読み、編集権を得る。
元の端末は閲覧のみになる。

引き継ぎでは、元の端末にだけある未同期の変更を引き継がない。
操作の前に、未同期の変更が失われることを確認する。

トレーニングの終了後は編集権を外し、同じアカウントのどの端末からでも編集できる。
同時に編集した場合は、サーバーが受理した保存時刻が遅い内容を残す。

端末トークンは、アカウントの認証情報から導かない。

## Consequences

引き継ぎでは、元の端末の未同期の変更が失われる。
確認の画面を出し、利用者が意図したときだけ引き継ぐ必要がある。

元の端末がオフラインのまま編集を続けた場合、サーバーはその書き込みを拒否する。
端末は編集権を失ったことを表示し、サーバーの内容を読み直す必要がある。

終了後の同時編集は後勝ちであるため、先に保存した内容は失われる。
PRD はこの扱いを定めている。

端末のブラウザストレージを消すと端末トークンを失い、編集権を失うが、引き継ぎで復旧できる。

端末トークンを盗まれた場合は、その端末として編集できる。
端末トークンは HttpOnly の Cookie で守る。
引き継ぎでは、そのトレーニングの編集権を新しい端末トークンに置き換え、端末トークン自体は無効にしない。
元の端末は、ほかのトレーニングを引き続き編集できる。

ほかの端末が見られるのは、サーバーに同期済みの内容に限る。
開始した端末がオフラインの間は、ほかの端末に最新の記録は見えない。

サーバーは、開始、引き継ぎ、終了の各時点で編集権の状態を持つ必要がある。
